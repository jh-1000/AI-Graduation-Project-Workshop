# 软件项目分析学习系统 — 实施计划（最终版）

> 本文档为经两轮工程修订后的最终定稿，整合产品设计（七轮迭代）、证据可信度体系、并发与恢复方案、安全边界与验证清单，可直接进入实施。

## 1. 产品定位、目标用户与核心价值

**AI 辅助开发者的项目理解与能力训练系统**（本地 Web 应用）。目标用户：能借助 AI 完成软件项目，但不真正理解项目代码、架构、业务流程与运行机制的人。

**两条学习主线**（同一套数据与机制承载）：
1. **理解项目**——项目由什么组成、业务如何流转、代码如何执行、数据如何变化、异常如何处理
2. **理解 AI 辅助开发**——AI 如何参与分析/设计/实现/审查/验证，用户如何识别 AI 错误、限制权限、核实结论

**四个核心能力**：端到端业务流程追踪；可核验的源码证据；主动回忆+纠错+间隔复习的学习闭环；有隔离、有验证、有回滚的实战修改挑战。

全系统围绕**同一套项目版本、事实、证据和验证记录**展开——学习、答辩、挑战、体检互相可追溯，不建平行知识体系。差异化：证据可自证、学习有闭环、实战有回滚，不是 Wiki 生成器。

## 2. 设计原则与非目标

**原则**：①证据优先——代码事实从源码/解析/实际验证提取，AI 负责组织解释、类比、练习，不负责产生事实；②主动回忆——"听懂"≠"掌握"，掌握必须有独立练习证据；③实战隔离——未授权不改真实文件；④被分析项目的源码/注释/README/脚本一律是数据不是指令；⑤前置知识按需补课——不假设用户懂术语；⑥渐进披露——十段内容规范不等于页面一次全展示；⑦简单解释不牺牲准确性——类比是起点不是事实替代品。

**非目标**（不进入任何阶段）：多用户/登录、云部署、实时协作、IDE 插件、移动端、AI 理论课程、二进制逆向、向量库全库 RAG、CI 服务、消息队列/工作流引擎/独立治理平台。

## 3. 总体架构与技术栈

**技术栈**：Next.js 15 App Router + TypeScript + Tailwind 全栈单体（`npm run dev` 本地起）；better-sqlite3（`serverExternalPackages` 配置，WAL 模式）；ts-morph + web-tree-sitter + 个性化 PageRank；ts-fsrs；Cytoscape.js（客户端动态加载）；Shiki（服务端高亮）；openai 包接 OpenAI 兼容 API（可配 baseURL/key/model）；独立 worker 子进程执行分析。

**模块职责**：

| 模块 | 职责 |
|------|------|
| app（UI + API routes） | 页面、交互、学习/答辩/挑战操作；不直接触碰文件系统，全部经服务端 API |
| worker（子进程） | 执行 Scan/Map/体检/git 考古/失效重算；写分析类表；心跳上报 |
| analyzer | Scan（扫描/消毒/栈识别）+ 结构分析（ts-morph / tree-sitter / PageRank） |
| llm-client | 分阶段调用、prompt 缓存、重试、zod 结构化校验、**出站过滤器**（§12） |
| evidence-core | claims/evidence/依赖传播/版本管理/覆盖统计 |
| learn / defend / challenge / regression | 学习闭环 / 答辩会话 / 挑战与隔离区 / fixture 回归评测 |

## 4. Scan → Map → Explore 端到端流程

**Scan（秒级，零 LLM 成本）**：授权路径或 zip 导入 → 文件清单、目录树、栈识别、路由表、API 端点、数据模型、依赖及真实版本（lockfile）。完成即固定**输入快照**：`run_files(run_id, path, size, mtime, sha256)`——**不复制源码内容**，以清单+哈希标识版本。单文件失败入跳过清单继续。UI 标注"初步清单"，不冒充完整分析。

**Map（worker，预算内断点续跑）**：每阶段开始前对**本阶段将读取的文件**重新计算哈希与快照核对——不匹配则该文件跳过并记 open_question（"分析期间变化"）；不匹配比例 >5% 或命中关键路径 → 整个 run 转 stale（原因"输入已变化"），提示重跑。分阶段：架构总览→模块深挖→业务流程还原→知识点生成→术语归并→建边→体检→git 考古→双重校验→覆盖统计。阶段产物即时落盘；每条结论携带证据引用与 `analysis_version`。

**Explore**：学习/答辩/挑战。渲染任何结论前校验 review_state 与 freshness——stale 显示"待复核"徽标并提供重新核查入口，不静默引用已失效事实。

## 5. 项目导入、静态分析与上下文选料

**导入**：本地路径 realpath 校验限定授权根目录（防符号链接逃逸）；zip 解压设总大小/条目数/单文件上限，消毒路径条目，处理 Windows 中文编码。

**选料**（aider repo-map 式）：web-tree-sitter 全库解析→符号引用图→个性化 PageRank→按 token 预算二分拟合选出喂 LLM 的代表文件。**职责边界：选料只决定 LLM 分析优先级与上下文预算，不决定覆盖统计口径**——代表性文件分析完成≠整库分析完成。

**两套解析器分工**：ts-morph 负责 TS/JS 深度语义（类型、引用、调用层级）；web-tree-sitter 负责全部语言语法树与符号抽取及 TS 快速初扫。产物统一映射到 `files`+`symbols` 表。冲突规则：TS/JS 以 ts-morph 为准。降级：解析错误/动态调用/类型缺失→符号标 approximate；语言不支持→仅文本扫描并计入覆盖报告未知范围。静态分析不声称可解析所有动态行为。

## 6. 事实、证据、结论与验证的统一模型

**三维度拆分**（不混用）：
- `origin`（来源）：source_code / static_analyzer / llm / user / runtime / unknown
- `derivation`（推导方式，结论字段）：direct_extraction / inferred / llm_interpreted / user_asserted / measured
- `review_state`（核查状态，结论字段）：draft → supported（证据直接支持+双重校验通过）→ reviewed；可转 flagged / superseded

**证据两维**：`processing`（extracted→linked→reviewed，处理进度）与 `freshness`（current 哈希一致 / shifted 行号已重映射 / stale 源文件已变，新鲜度）。

**运行验证**：独立实体 runtime_proofs，与 claims 多对多关联；**8 类标签**：static_lint / type_build / unit_test / integration_test / e2e_test / api_behavior / business_rule / manual_review。每条记录：类型/命令参数/环境/时间/授权依据/输出摘要/**断言范围**/结果/未覆盖场景/项目版本。**运行验证不是结论必经状态**——未经运行验证是正常状态而非缺陷；结论 verified = 存在断言范围覆盖其声称范围的验证记录；任何验证成功不得扩大解释为整个项目正确。

**三个独立总状态**：分析任务完成（含记录在案的失败与跳过）/ 覆盖充分（达预定义标准）/ 结论已验证（与声称范围匹配的验证证据）。不得合并为笼统的"分析完成"。

**证据层 E1-E4**（直接事实/结构关系/机制推断/运行验证）只描述依据深度、各层有各自核查规则，与授权层 Auth-L0~L6（§12）互不混淆。

**七条不等式**（UI 与文案遵循）：文件存在≠结论正确；一段源码≠证明整流程；静态成功≠运行正确；构建成功≠测试通过；测试通过≠业务正确；覆盖某路径≠全分支已验证；AI 置信度≠统计校准的正确概率。

**可信度七原则**：①代码事实优先 ②AI 不产生事实 ③评分引用预置要点+项目证据 ④无法验证的标推断/未知并给下一步核查 ⑤冲突时以核实事实为准，保留 Correction 三段式（原声称/现验证为真/逐字证据）⑥"听懂"≠"掌握" ⑦通用知识标适用版本，示例/类比/推测不冒充项目实际行为。

## 7. 证据生命周期、版本管理与失效传播

每次 `analysis_runs` 生成唯一版本；claims/evidence/nodes/flows/答辩题/挑战基线均记录 `analysis_version`。**版本绑定六类**：工作区版本/最近分析版本/学习内容版本/答辩练习版本/挑战基线版本/挑战结束版本——不一致时 UI 必须显示差异；答辩引用的旧证据不得悄悄变成当前事实。

**失效传播（解析器语义差异驱动，不做无害假设）**——变更文件重解析并与快照 AST 对比：

| 判定 | 处理 |
|------|------|
| AST 等价（仅注释/空白差异，由解析器证明） | 仅 freshness=shifted，diff 对齐重映射行号，结论保留 |
| AST 有差异 | 按差异节点定位受影响符号 → 直接证据/结论 stale → claim_dependencies 多跳传播 → flows/nodes → 答辩题 → 挑战基线 |
| 无法解析/语言不支持/解析失败 | **保守失效**：该文件全部结论 stale（原因"无法判断变化影响"） |
| 依赖版本变化 | 引用该依赖的结论 + 术语版本标注失效 |
| 测试变化 | 相关 runtime_proofs 转历史，不冒充当前 |

学习记录保留：知识点实质变化→mastery 降"练习中（需重验）"，历史成绩不删除。

## 8. 数据模型（SQLite，四批建表）

**P0（核心链路）**：`meta`（schema_version）/ `projects`（授权根目录/答辩任务书/日期/授权开关）/ `files`（哈希/解析方式 parsed|text_only|skipped）/ `symbols`（统一符号表：file_id/名称/类型/识别方式/精度 exact|approximate）/ `analysis_runs`（版本/阶段/状态/预算/恢复位置/心跳/恢复计数）/ `run_files`（快照清单）/ `evidence`（文件/行范围/哈希/origin/processing/freshness）/ `claims`（内容/derivation/review_state/置信/分析版本）/ `claim_evidence` / `claim_dependencies` / `edges`（类型+来源标注）/ `terms` / `open_questions` / `llm_cache`（键=提示词模板版本+全文+模型参数+输入哈希）/ `coverage_stats` / `regression_specs`+`regression_results`。

**P1**：`flows`+`flow_steps`（模板字段）/ `nodes`（10 段 JSON）/ `node_prerequisites` / `challenges`+`challenge_runs`（run_type=locate|modify|mutation）/ `learning_attempts`（最小字段）。

**P2**：`repo_insights`（体检发现）/ `history_events`（git 演进）/ `runtime_proofs` / `fact_conflicts`（Correction 三段式）/ `user_corrections`（不得直接覆盖源码事实）。

**P3**：`node_mastery`（六维 + FSRS D/S/R + 证据强度 + 迁移检查）/ `term_relations` 扩展（CONFUSED_WITH 承载混淆对比卡）。

**合并决策**：mutation_experiments→challenge_runs.run_type；ai_playbooks→nodes/challenges 的 JSON 字段；glossary_confusions→术语关系。分析数据与学习记录分离，重跑按稳定 key 保留 mastery。

## 9. 业务流程模板与六维覆盖报告

**flows 模板可配置**（不强加五段链）：默认"交互式应用"（用户操作→前端处理→接口与后端→数据变化→结果返回）；内置"后台任务/命令行"（触发→入口→处理→数据变化→输出副作用）、"数据管道"（来源→转换→存储→消费→反馈）、"库/模块"（调用方→入口 API→核心逻辑→状态变更→返回）。Scan 按栈建议模板，用户可改。每步四入口：看懂/看代码（file:line 跳转）/追下去（含反向追踪）/考考我。业务功能与执行机制用边关联不混层。

**六维覆盖报告**（每维给：目标范围/已完成/失败/跳过原因/待处理，不用模糊百分比掩盖关键流程缺失）：①文件解析 ②符号识别 ③引用关系 ④业务流程识别 ⑤外部依赖 ⑥运行验证。PageRank 未选中的文件如实计入"未覆盖"。

## 10. 学习闭环

**零基础入口（首屏）**：目标导向卡片（"整体怎么运行""AI 写的代码怎么看""老师问我怎么实现怎么办""怎么知道 AI 写对没"…）+ 自然语言路由（**匹配不确定时展示少量候选并说明对应内容，不强行给唯一答案**）+ 五站导览（认识项目→走通功能→关键机制→答辩拷问→独立修改验证）。

**知识点页十段**（生成规范，渐进呈现）：默认展开①先说人话 ③生活类比（及边界）④最小示例；②前置知识以 chip 呈现；⑤在我的项目中⑥运行时发生了什么⑦容易理解错的地方⑧我能否自己解释⑨答辩可能怎么问⑩深入学习 折叠按需展开。**三档模式**（同一份核验事实，不因一次答错降档）：从零开始 / 结合项目学习（默认）/ 深入原理。

**前置知识识别与按需补课**：Map 阶段同步输出"理解所必需"的前置概念（注明为何必需），只识别阻碍理解的部分；按需逐层深入（先答"为什么这里要等待"，追问才展开事件循环）；术语中心任何术语可点——通俗+专业定义/最小示例/误区/`_Avoid:_` 别名，每条标**通用知识/项目特定用法/待核实**；涉及当前代码展示整库实际用法；学完返回原阅读位置。

**可纠偏学习路径**（两次失败=初始启发式，非固定阈值，按错误类型切换）：能解释不能定位→切定位练习；能定位讲不清数据流→切流程练习；熟题能答新问法不能→出迁移题；迷失可返回主线；已掌握跳过讲解直接验证。

**六级主动回忆**：选解释→自己解释→找代码→补调用链→解释错误与理由→修改并验证；答错阶梯提示（小提示→具体提示→最后才给答案）。**掌握度与调度分离**：ts-fsrs 只管复习时间调度（D/S/R）；掌握判定靠独立证据（题型/难度/提示依赖/是否看答案/是否重复作答/是否迁移；同一题重复答对不算多份证据；看过答案的答对不与独立回答等价）；三态：未学习/练习中/已验证掌握。**效果评估七项**：复述流程/行为定位代码/解释数据传递/识别成败路径/换问法/新场景迁移/独立定位并验证——只记学习结果，不采个人信息，不打固定能力标签。

**其余**：寓言卡四段（故事不点破→反转揭晓→映射解释→回到项目+类比不成立处）；学习记录四触发（非平凡理解/披露既有知识/误解纠正=最高价值/目标变化），mere coverage 不写，superseded 不删；AI 协作实践双重闭环（项目能力+AI 使用能力：先调查→最小方案→验收条件→审查差异→验证→亲自解释；脚手架逐级撤除）；混淆对比卡；全局学习助手（用已存证据回答，不足明说缺口+下一步核查）；答辩冲刺模式（按日期出每日计划，按任务书+关键链+薄弱点裁剪，可随时调整）。

## 11. 答辩模拟与实战挑战

**答辩模拟**：grill 协议（一次一问→针对回答缺口追问→阶梯提示→最后"不看答案复述"）；**双轴独立评分不合并总分**（轴 A 代码事实自洽 / 轴 B 兑现声称程度）；AI 辅助开发题型库（为什么这样实现/关键判断/怎么验证 AI 没遗漏异常/给错方案怎么发现/改动影响哪些模块/不用 AI 怎么定位）；体检题源须标"疑似"，不当确定缺陷；每题绑定项目版本与证据；评分观察：区分已理解 vs 依赖 AI、用代码证据判断、说明验证过程、独立解释。

**实战挑战八要素**：目标/起始基线/允许修改范围/禁止操作/验收条件/验证方式/回滚方式/失败恢复。类型：定位（文件树点选，整库引用图核验）/修改（隔离 worktree+diff+验证命令+一键回滚）/破坏实验（删改一处→运行观察→解释为什么需要它→还原）。**结果三态区分**：代码已修改 / 验证命令已执行 / 验收条件已满足——不等价，分别展示。**worktree 不是沙箱**：基线固定（含未提交修改提示）、修改范围记录、测试命令独立副作用审查（不信 package.json）、超时/终止/输出上限；非 git 项目用副本工作区+原文件备份。

## 12. 权限授权与安全边界

**分层授权 Auth-L0~L6**（每项含：默认/授权/范围/复用/失效/撤销/记录）：

| 级 | 操作 | 默认 |
|----|------|------|
| L0 | 只读扫描与静态分析 | 导入即授权根目录 |
| L1a | 使用模型服务 | 首次授权 |
| L1b | 发送项目内容范围 | 首次发送前列文件清单与字符量确认，范围变更需再确认 |
| L2 | 执行构建/类型检查/测试 | 单次授权或项目开关，命令独立副作用审查 |
| L3 | 访问网络/数据库/外部服务 | 默认拒绝，逐次授权 |
| L4 | 真实数据/外部副作用环境 | 默认拒绝，明确警告 |
| L5 | 修改项目文件（挑战） | 项目级开关默认关+单次确认 |
| L6 | 提交/推送/部署 | 不提供，提示用户自行操作 |

低风险不被繁琐授权阻塞；高风险不因曾授权低级而默认获得。

**LLM 出站过滤器（发送前强制）**：①敏感文件默认排除（.env*、*.key、*.pem、id_rsa*、credentials* 等，用户可查看调整）②内容级密钥检测（高熵串/常见密钥格式）→命中片段遮蔽 `[REDACTED]` 并计数 ③发送清单与大小上限透明可配 ④SSRF 防护：baseURL 限 http(s)、解析后校验 IP 拒绝私网/环回/链路本地（**用户明确授权本地模型如 Ollama 后放行**）、禁自动重定向逐跳重校验、超时/响应上限/限流处理 ⑤每次调用记录发送文件数/字符量/遮蔽次数（不含内容）。密钥只写不读（GET 掩码）、不进日志/错误栈/缓存键/导出/提示词。

**文件安全**：路径穿越/符号链接逃逸（realpath 前缀匹配）；zip 炸弹/超大文件/超深目录/循环链接防护；权限错误入跳过清单；临时文件用后即清。

## 13. 任务状态机、并发写入与恢复

**状态机（6 状态）**：`queued / running / paused / completed / failed / cancelled`。转换：queued→running|cancelled；running→paused|completed|failed|queued（心跳超时自动重排，恢复计数>3→failed"反复中断"）；paused→running|cancelled；failed/cancelled→queued（手动重试）。**interrupted 不是状态**：worker 死亡/服务重启由启动恢复流程处理（心跳超时的 running→queued，保留恢复位置）。

**键分离**：任务幂等键 = hash(快照 ID+分析配置+分析器版本+提示词版本+模型参数)；llm_cache 键 = hash(提示词全文+模型参数+输入内容哈希)。同任务重跑经缓存变廉价；输入变→提示词变→自然 miss。**暂存模型响应不是绝对保证**：写缓存失败（磁盘满/BUSY）→该结果作废、任务转 paused、稍后重试。

**SQLite 并发（诚实方案）**：SQLite 同一时刻仅一个写事务，WAL 下读不阻塞写。**不做跨进程写协调者**：app 与 worker 均直写各自范围的表，约束=短事务（批量写入分批 <100ms）+busy_timeout 5000ms+SQLITE_BUSY 指数退避重试（≤5 次）；超限→阶段事务回滚、任务转 paused 记录恢复位置。**压测验收**：fixture 上同时 2 个分析任务+UI 写操作 10 分钟——0 数据丢失、无永久 BUSY、`foreign_key_check`/`integrity_check` 通过、coverage_stats 与实际行数一致。

**故障对策（12 类）**：浏览器关闭（无影响）/worker 崩溃与服务重启（心跳+启动恢复）/SQLite 写失败（重试）/迁移中断（事务化迁移，失败→回滚+维护模式页不自动重试）/LLM 超时（重试+断点）/结果未写库（暂存规避+失败作废）/重复启动（幂等键）/取消残留进程（taskkill /T+启动清理）/分析中源文件变化（快照核对 §4）/部分写入（阶段事务）/状态不一致（启动校验修复）。

**备份**：better-sqlite3 `db.backup()`（SQLite Online Backup API，写压下产出一致快照）——定时（每日+每次分析完成）+手动导出；恢复校验：integrity_check+关键表行数比对，失败保留前一份并告警；磁盘空间预检（≥db×1.5）；**明确限制：进程被强杀无法执行关闭备份，不承诺关闭时自动备份**。

## 14. 回归评测与质量指标

**三个 fixture**（逐步复杂，均含人工核验预期结果：文件符号识别/关键引用/已知流程/成败路径/证据位置/应发现开放问题/**不应断言为事实的内容**/预期题目/已知运行验证结果）：①简单 TypeScript 项目 ②前后端分离项目 ③循环依赖+复杂状态流转项目。

**回归触发**：任何解析器/提示词/数据模型/核心流程变更后必须执行。**回归 10 项检查**：符号识别退化/引用关系退化/流程关键步骤丢失/证据位置错误/失效传播正确/新增无证据结论/题目与项目版本一致/学习记录被错误重置/**任务恢复与并发一致性**/安全边界完好。

**失败九分类**（不统一标"AI 分析失败"）：解析失败/分析遗漏/证据定位错误/结论错误/无法判定/运行环境问题/业务行为错误/学习内容质量问题/系统自身故障。

**质量指标**：结论准确性、关键路径覆盖、证据支持程度、学习任务完成效果。**不采用**：节点/边/题目数量、生成文本长度、AI 自评分。
